# NEAR-CIRCLE — DEVELOPMENT PROMPT 01
## Phase 1: Project Foundation and Mock Messenger Interface

You are the lead software engineer responsible for implementing Near-Circle, a standalone application for the Meta Global AI Hackathon.

### 1. Authoritative project references

Before writing code, read both files from the current project root:

- `./Near-Circle_Dev_Plan.md` — **authoritative technical specification**
- `./Near-Circle_Dev_Plan_visual.pdf` — **visual architecture and user-experience reference**

Follow the Markdown for architecture, requirements, service boundaries, implementation phases, and acceptance criteria.

Follow the PDF for layout, visual presentation, interaction flow, and especially the illustrated four-screen user journey.

If technical descriptions differ, the Markdown takes precedence.

If either document is missing or cannot be read, report the issue rather than inventing its contents.

### 2. Phase 1 objective

Build the foundational Near-Circle application, including:

- A functional Messenger-inspired prototype.
- Seeded demo friends and conversations.
- An interactive Near-Circle entry point.
- A basic visibility toggle.
- A Fastify backend foundation.
- Project-owned PostgreSQL/PostGIS infrastructure.
- An independent pedestrian OSRM service boundary.
- A unified development launcher.

Do not implement actual friend proximity, routing, or AI integration in this phase.

### 3. Required service architecture

Establish four independent local services:

1. **Frontend:** React, Vite, TypeScript.
2. **Backend:** Fastify, TypeScript.
3. **Database:** PostgreSQL with PostGIS.
4. **Walking router:** OSRM with a dedicated pedestrian profile.

Use project-owned Docker Compose configuration.

The OSRM service may be scaffolded initially. Do not declare pedestrian routing functional until a dedicated foot-profile graph has been prepared and tested.

OpenStreetMap-compatible map tiles must remain an external, configurable dependency by default.

Maintain clear boundaries between services and avoid dependencies on unrelated local projects.

### 5. Unified server management

Implement these project-root commands:

```powershell
npm run startall
npm run stopall
npm run status
```

**startall**

- Launch implemented local services.
- Check actual readiness.
- Display accessible URLs.
- Report service health.
- Identify incomplete or unprepared services accurately.

**stopall**

- Gracefully stop only Near-Circle services.
- Preserve database volumes and routing artifacts.
- Do not modify unrelated Docker containers.

**status**

- Report running, stopped, unhealthy, unreachable, and not-yet-ready services.
- Perform non-destructive readiness checks.

Use PowerShell 7-compatible scripts.

Do not rely on arbitrary fixed delays for service readiness.
