# Near-Circle — Messenger UI Redesign & Hackathon Presentation

**Model:** Muse Wonder 1.0

**Project:** `E:\hacathon\meta\near-circle-friend`

## Objective

Redesign the existing Near-Circle frontend to create a polished, high-fidelity concept showing how Near-Circle could function as a **native feature within Facebook Messenger**.

This application is being developed for the Meta Global AI Hackathon 2026.

Our goal is to help judges immediately recognize the familiar Facebook/Messenger experience while demonstrating how Near-Circle extends it with proximity-based social discovery.

**Important:** This is a frontend presentation and user-experience improvement, not an architectural rewrite.

## 2. Facebook / Messenger Visual Identity

Redesign the frontend to closely resemble the contemporary Facebook Messenger desktop experience in its visual language, interaction patterns, layout, and overall presentation.

The objective is a convincing product concept that looks naturally integrated into the Messenger ecosystem.

### Design characteristics

- Familiar Facebook-inspired blue accent colors.
- Messenger-style navigation and typography.
- Clean white and soft-gray interface surfaces.
- Circular profile avatars.
- Familiar conversation list and search interface.
- Realistic message bubbles and timestamps.
- Natural chat spacing and alignment.
- Rounded controls and subtle borders.
- Professional icons, hover states, and transitions.
- Consistent desktop and responsive mobile presentation.

Avoid unnecessary decorative elements that make the interface resemble a generic SaaS dashboard.

Use original UI implementations and assets. Do not copy unauthorized proprietary logos, artwork, or other protected resources.

The desired result is visually familiar and convincing without falsely presenting itself as an official Facebook or Messenger application.

## 3. Messenger Layout

Design the interface around three primary regions.

### Left — Messenger Navigation

Include:

- Messenger-inspired header.
- Chat search.
- Simulated conversations.
- Circular friend avatars.
- Recent-message previews.
- Timestamps.
- Unread indicators.
- Active conversation highlighting.

The interface should feel like a genuine messaging environment.

### Center — Conversation Area

Include:

- Selected friend's profile and name.
- Conversation history using existing mock data.
- Messenger-style message bubbles.
- Timestamp separators.
- Message composition interface.
- Familiar action controls.

Preserve the current simulated conversation functionality.

Do not introduce fake production messaging capabilities.

### Near-Circle Entry Point

Introduce a prominent but naturally integrated **Near-Circle** action.

It should appear where a Messenger user would intuitively expect an additional social-discovery feature.

Possible placement:

- Conversation header action.
- Main navigation shortcut.
- Dedicated Near-Circle icon alongside messaging features.

Select the most convincing layout based on the existing interface.

The action should feel like a native Messenger extension rather than an unrelated embedded application.

## 4. Near-Circle Radar Experience

Preserve the existing functional radar.

Improve its appearance so it feels visually integrated with Messenger.

Requirements:

- Current user centered on the radar.
- Nearby opted-in friends represented by red dots.
- Concentric proximity rings.
- Configurable discovery radius.
- Smooth, restrained radar animations.
- Clear friend selection states.
- Friend profile preview on selection.
- Responsive layout.
- Accessible controls.

The radar should have its own visual personality while remaining consistent with the Messenger-inspired design system.

Do not replace genuine PostGIS discovery results with hardcoded frontend data.

- Walking distance.

## 6. Product Demonstration Flow

The application must support this complete experience:

1. User opens the Messenger-style interface.
2. User sees familiar conversations and friends.
3. User selects Near-Circle.
4. Near-Circle displays nearby opted-in friends on the radar.
5. User changes the discovery radius.
6. User selects a nearby friend.
7. User sees the friend's profile and walking-route option.
8. User opens the pedestrian route map.
9. User sees distance, ETA, and estimated steps.
10. User returns smoothly to Messenger or the radar.

This experience should feel like one cohesive application.

Avoid jarring transitions, inconsistent layouts, and unnecessary navigation.
